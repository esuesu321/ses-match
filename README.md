# SES MATCHの使い方・起動方法

株式会社jioworks向けのSES営業支援アプリの初期版です。案件一覧、要員一覧、案件と要員のマッチング、LINE案件の手動投入を利用できます。通常は手元の端末で動作します。本人専用の複数PC運用に向けてHTTPSプロキシ経由の認証を追加しました。配置方法と未完了事項は[DEPLOYMENT.md](DEPLOYMENT.md)を参照してください。

## 起動方法

動作にはNode.jsの24以上が必要です。初回に`npm ci --ignore-scripts`で依存ライブラリをインストールします。

1. このアプリのフォルダをターミナルで開きます。
2. `npm start` を実行します。
3. [SES MATCHの画面](http://127.0.0.1:4317/)を開きます。

停止する場合は、起動したターミナルで「Ctrl+C」を押します。保存データは `data/ses.sqlite` にあり、再起動後も残ります。プロジェクトの参照資料がある `../sources/` は変更しません。

## 案件登録からマッチングまで

1. 「LINE案件を投入」で本文を貼り付け、「項目を抽出して確認」を押します。
2. 抽出内容を原文と照合し、商流・年齢・出社条件・募集状況などを確認して保存します。不明な条件は空欄または「要確認」のまま保存できます。
3. 「要員一覧」で要員を登録します。商用実務の期間、使用スキル、担当工程、出典を入力します。
4. 通勤情報には、実際に確認した勤務地、片道の所要時間、許容時間を記録します。常駐可だけで全国対応とは判断しません。
5. 「マッチング」で対象を選び、照合を実行します。根拠と確認事項を確認し、必要な内容をコピーできます。

入力例は架空案件です。実在する募集中案件として扱わないでください。案件・要員の登録や編集後は、以前のマッチング結果を消し、再実行できる状態にします。

要員の営業サマリは、プロジェクトの固定フォーマットで表示・コピーできます。情報がない項目は「要確認」と表示し、PR・備考を含む全項目を固定順で表示します。「要確認」は未経験・不可を意味しません。

## 判定の基本

外国籍・個人事業主・商流や所属・年齢・勤務地や通勤・常駐やリモート・単価・開始時期を確認します。

明確な制限に該当する組み合わせは「対象外」とし、標準表示から除外します。記載がない条件は「不可」と推測せず「要確認」とします。「対象外も表示」で除外理由を確認できます。

商用実務の期間と出典が確認できる経験だけを実務年数に算入します。個人開発・研修・自己学習は算入せず、重複期間も二重に数えません。

## AI評価の設定

営業条件は、あらかじめ定めたルールで判定します。AIは役割・経験内容・説明可能な不足について補助的な所見を付けます。AI所見で「対象外」を解除しません。接続設定がない場合は「AI未接続」と表示します。

設定用の見本ファイル `.env.example` を `.env` としてコピーし、次の項目を設定して再起動します。設定名はプログラムが使用するため、表記を変えないでください。

|設定名|日本語での意味|入力する内容|
|---|---|---|
|`AI_ENDPOINT`|AIへの問い合わせ先|会話形式の問い合わせに対応するサービスの完全な接続先URL。技術的にはChat Completions互換の形式を使用|
|`AI_API_KEY`|AI接続用の認証キー|接続先サービスで発行したキー|
|`AI_MODEL`|利用するAIモデル|接続先で使用できるモデルの識別名|
|`PORT`|画面を開くための接続番号|通常は4317。変更した場合は画面を開くアドレスの番号も変更|

認証キーは、画面へ渡さずサーバー側で使用します。AI評価では案件・要員情報を外部サービスへ送信するため、接続先とデータの取扱いを社内で確認してください。

画面で「AI評価を追加」を選択すると利用できます。一度に10組まで評価し、1組あたり30秒を超えた場合は待機を打ち切ります。未接続・未実行・省略・失敗・完了を区別して表示します。AI評価に失敗しても、ルール判定は表示できます。AI所見は営業担当が確認してください。

接続形式の参考：[AIから決められた形式の回答を受け取る公式ガイド](https://developers.openai.com/api/docs/guides/structured-outputs)。リンク先は外部の公式資料です。実際のAIサービスへの接続は、認証キーが未提供のため未検証です。接続処理の正常時・異常時は、動作確認用の模擬サービスで検証しています。

## 現在の範囲と今後の追加

現在は、1人が使う初期版です。HTTPSプロキシ経由の本人認証を実装しました。同じ自己管理サーバーへ2台から接続する構成は[配置手順](DEPLOYMENT.md)に記載しています。実サーバー配置と2台の実機確認は未完了です。利用者ごとの権限管理は未実装です。

Gmail・Googleドライブからの自動取り込みは未接続です。LINEでは、コピーまたは共有したテキストを貼り付ける運用です。端末の共有メニューから直接このアプリへ送る機能は未実装です。

今後の取り込みは「取り込み元との接続」→「原文保存」→「項目整理」→「人による確認」→「登録」の順で追加します。Gmailのメール・会話、Googleドライブのファイル・更新版を識別し、同じ情報を繰り返し登録しないようにします。

メール本文の確認、募集継続の確認、複数社から届く同一案件の整理を組み込みます。現在の重複検知は、全角・半角などの表記を揃えた本文全体の一致だけです。似た案件を自動で統合する機能はありません。

複数人での利用へ進む場合は、個別ログインと利用権限を追加します。現在の保存にはSQLiteを使用しています。Node.jsに組み込まれた保存機能が実験段階であることを示す通知が表示される場合があります。

## ChatGPT契約枠の接続（実接続は未検証）

Windowsの場合は、ZIPを展開してCONNECT_CHATGPT.cmdをダブルクリックします。
Node.js 24以上が必要です。依存ライブラリを導入し、ブラウザで本人の認証を行った後、架空の短文で接続確認します。
成功時は黒い画面に「SUCCESS: ChatGPT plan connection was verified.」と表示されます。
実際の本人PCでの動作確認はこれからです。

OpenAIの公式OSS手順に沿ったOAuth接続、モデル取得、Responsesのストリーミング評価を実装しました。
別料金APIへの自動切替はありません。`.env`の`SES_AI_MODE=chatgpt`を指定します。
PCで`npm run chatgpt:connect`を実行し、表示されたURLを**同じPCのブラウザ**で開いて許可します。
`npm run chatgpt:verify`は架空の短文だけで実接続を確認します。
認証情報はユーザープロファイル内の保護した保存先に置き、ブラウザやGitHubへ渡しません。
サーバーへの移送と接続検証の順番は[配置手順](DEPLOYMENT.md)を参照してください。
実アカウントでの認証・利用枠・モデルアクセスは未検証であり、実装済みと接続成功を区別します。

画面と保存項目の詳しい説明は、[画面・データ設計](DESIGN.md)にまとめています。

## 提案候補とおすすめ（2026-10-13）

マッチング結果は「おすすめ候補（最大5件）」と「提案候補の全件一覧」を両方表示します。
おすすめは必須スキル・担当工程の証跡付き実務が一致する候補から選びます。契約・営業状況の未確認、条件調整の有無で優先順位を付け、理由を表示します。
順位は登録条件に基づく目安です。AIが案件全体を比較した推薦ではなく、AI所見は別に確認できます。
おすすめに選ばれなかった候補も全件一覧に残し、問題なし・要確認・懸念ありで絞り込めます。
参画決定済み・営業休止の要員は対象外。古い登録に営業状況がない場合は要確認とし、勝手に営業中へ変更しません。
サマリの未記載項目は「要確認」と表記します。
本人PCでChatGPT契約枠の短文応答と架空データのAI所見表示を確認済み。サーバー運用と実案件での推薦精度は未確認です。

### メール本文からの案件取り込み（2026-10-13）
左メニュー「メール案件を投入」で件名・受信日・1案件分の本文を入力できます。手動抽出、または接続済みChatGPT契約枠によるAI抽出を選び、原文・引用根拠と条件を照合して保存します。抽出APIはデータを保存しません。同一本文の登録を検知します。未記載の支払いサイトは35日を初期値とし、確認事項として表示します。

AI抽出では件名と本文を送信します。一般的なメールアドレス・電話番号は送信前に除去しますが、完全な匿名化ではありません。氏名・会社名・署名など不要な情報は入力前に削除してください。元の本文はアプリのデータベースに保存します。メール本文・個人情報・接続認証情報は公開ソースや配布ZIPに含めません。AIの引用は原文との文字列一致を検査しますが、意味の解釈の正しさを保証しないため人の確認が必須です。Gmail自動同期・添付解析・複数案件の自動分割は未実装です。AI通信失敗時に有料APIへ切り替えません。

検証：自動テスト59件通過、構文確認通過。実際のChatGPT接続を使ったメール抽出の確認はユーザー端末での動作確認が必要です。

### 取り込み精度の改善（2026-10-13）
角括弧・記号・コロンの見出しで必須と尚可を分離します。単価の下限・概算・条件付き可否・年月だけの開始日・不正日付は確定値へ補完しません。重複した条件の矛盾を勝手に一方だけ採用しません。支払い日数・商流・面談・募集人数・担当工程は明記された書式から抽出します。複数の案件名があるメールは1件ずつ分けるよう求めます。注意点は登録画面内にも表示します。

AI抽出の引用一致に加え、契約可否・単価・開始日の食い違い、尚可を必須に変更、引用にない技術、必須年数の変更・削除を検査します。読み取れない契約可否は要確認へ戻し、単価上限・開始日は確定しません。検査は既知の書式が対象で、すべての自然文を理解するものではありません。原文確認が必要です。テスト86件通過。実ChatGPT接続による新版抽出とブラウザの表示確認は未実施です。

### 複数画面からの上書き防止（2026-10-13）
案件・要員にサーバー発行のrevisionを付与し、更新・削除時は読込時点のrevisionを必須にしました。古い画面からの更新・削除は409、版情報なしは428で拒否します。旧DBは読み出す際に安定した版情報を付与し、事前移行なしで編集できます。古いクライアントは更新できないため、公開運用時は新版へ再読み込みが必要です。

保存競合時は入力を残し、今回の入力と最新保存内容を比較します。別々の項目は両方を引き継ぎ、同じ項目は利用者が採用する値を選びます。経験などの配列は配列全体を1項目として扱います。比較後は編集画面に戻り、再確認してから保存します。自動保存や強制上書きはしません。

自動テスト90件通過。APIで同時更新の片方だけが成功すること、古い版による削除・版情報なしの拒否、旧レコード対応、再競合時の未保存入力保持を検証済み。実ブラウザの比較画面と実際の2台のPCでの操作は未検証です。対応範囲は単一Nodeプロセス・単一SQLiteでの運用です。
